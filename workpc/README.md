# Full-size KMCS check on the work PC

This package runs the corrected development code on the simulator's built-in **5 × 5 DOE grid**. It does not change the hopping energies or fit the model to the reference data. The published Python implementation is included separately for an optional matched comparison.

## Start here — Windows

1. Extract the whole ZIP into a local folder, preferably outside OneDrive. Do not run it from inside the ZIP.
2. Open `workpc` and double-click **01_SETUP_WINDOWS.bat**. You need Python **3.12** installed (with the Windows Python launcher) and internet access for the first dependency installation. Ask IT if installation is restricted. Setup validates the full plan and runs one tiny test; it does **not** start the full DOE.
3. When setup succeeds, double-click **02_RUN_OR_RESUME_WINDOWS.bat**. Leave the window open and keep the PC awake. The script does not change your computer's sleep settings.

The default is **25 corrected-code simulations**, with up to four running independently at once. These are full-size calculations: allow substantial time, potentially days or longer. The tiny test is not a runtime estimate. High-temperature, low-frequency conditions are particularly expensive. This package has not yet established full-size scientific agreement.

## Fixed comparison settings

| Setting | Value |
|---|---|
| Temperatures | 700, 750, 800, 850, 900 °C |
| Frequencies | 0.5, 2, 10, 20, 50 Hz |
| Lattice | 128 × 128 × 35 cells |
| Substrate step parameter | W = 1 |
| Deposition | 300 pulses, 0.04 ML per pulse |
| Film species | 2 (LMO) and 3 (LLTO), in a 1:2 ratio |
| Random seed | 42 |
| Energies | Original default matrix; species 4 is unused |
| Density analysis | Species 2; minimum 3 pixels; 8-connected features |

Settings are in `full_doe_config.json`. The wrapper calls the real `KMCS.run_doe` function separately for each condition so completed conditions can be resumed. Conditions are scheduled from lower temperature and higher frequency first. Parallelism uses separate processes, not threads.

The event limit is 100,000,000 per pulse, a safety ceiling, **not** a way to shorten relaxation. A case that reaches it, fails, or violates the saved-state integrity checks is excluded from the comparison and visibly marked. Do not call such a case validated.

## Progress, stopping and resuming

Results live in `workpc_results/corrected`. Each condition has a `case.json` status record and an attempt folder with a `run.log`, snapshots and `run_info.txt`. The combined `doe_results.csv` updates after every condition.

For a clean pause, create an empty file named **PAUSE_AFTER_CURRENT** (no extension) inside `workpc_results/corrected`. The currently active conditions finish, then no new ones start. Remove that file and double-click the run launcher to continue.

If the window is closed or the computer restarts, run the same launcher again. Completed conditions with an existing final snapshot are skipped. An interrupted condition starts again from its beginning in a new attempt folder; there is **no mid-simulation restart**. Earlier attempt folders are preserved.

The saved manifest prevents accidentally mixing different code, settings or Python/NumPy versions in one result folder. If you intentionally change these, choose a new output folder. To reduce CPU use without changing the scientific settings, run from the package's main folder:

```powershell
.venv\Scripts\python.exe workpc\run_full_doe.py --workers 2
```

## Looking at the results

Double-click **03_REFRESH_ANALYSIS_WINDOWS.bat** whenever you want refreshed plots without starting simulations. Open `workpc_results/corrected/analysis/REPORT.md` in a Markdown viewer, or open the PNGs directly:

- `density_heatmap.png`: the new 5 × 5 density grid.
- `reference_trends.png`: new curves alongside the supplied experiment, original-paper KMC and verified Python DOE trends, normalized independently.
- `topviews.png`: all 25 final top views, with pending or invalid cases labelled.
- `density_comparison.csv`: new densities and the fixed historical Python DOE values where available.
- `summary.json`: completion and basic trend checks.

Partial results are clearly counted; wait for **25/25 valid runs** before interpreting the full grid. One seed does not measure stochastic variability, and a matching slope alone is not proof of scientific equivalence. Inspect the images and complete sweeps too.

The paper's frequency sweep includes **8 Hz**, while the built-in grid uses **10 Hz**. They remain distinct. The historical Python DOE table has no **900 °C / 0.5 Hz** result, so that reference cell stays blank. `DOE_plot.py` contains the fixed historical table; it does not analyze these new runs. The report is generated by the separate work-PC analysis script.

When finished, ZIP the whole `workpc_results` folder to bring back for review. Keep the package and its manifest too. No need to include `.venv` or the tiny `workpc_smoke_results` folder.

## Optional: the published Python baseline

The default does **not** run another 25 simulations automatically. For the same full grid using the archived public Python code, run:

```powershell
.venv\Scripts\python.exe workpc\run_full_doe.py --engine published
```

These outputs go into `workpc_results/published`. The frozen source in `published_reference/KMCS.py` comes from public commit `c1b05906d06d762b451ee8349b1f2ef377a46b7e`; it is not the MATLAB implementation. Both engines use identical explicit settings. Baseline bugs are deliberately preserved for comparison, so its images need not match individual corrected trajectories.

To refresh its report:

```powershell
.venv\Scripts\python.exe workpc\run_full_doe.py --engine published --analyse-only
```

## Other operating systems

Use Python 3.12, create a virtual environment, install `requirements-tested.txt`, then run `workpc/run_full_doe.py --check` and `--smoke-test` before starting the default run. The Python scripts are portable; the double-click launchers are Windows-only.

This is a **local development validation package**, not a replacement for the archived v1.0.0 release. Preparing it has not changed the public repository or the 4TU deposit.
